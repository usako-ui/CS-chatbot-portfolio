## 実装時に注意する点

- **#3 と #4 は文面が似ているが挙動が逆になる。**
  #3（破損）は FAQ No.9 に回答があるのでAIが答える。
  #4（請求二重）は FAQ に一切記載がないのでエスカレーションする。
  この線引きは「FAQに書かれていないことは答えない」というシステムプロンプトの制約で担保する。

- **#4・#5 の判定根拠が違う。**
  #4 は「FAQに該当なし」による引き継ぎ、#5 は「感情的なクレーム」による引き継ぎ。
  どちらも `waiting_operator` へ遷移するが、エスカレーション理由を分けて記録できるようにする。

- **#6 はFAQ差し替えによりリスクが上がっている。**
  差し替え前の暫定FAQには「個別のご事情は担当者が対応します」という逃げ道を各回答に書いていたが、
  講座提供の正式FAQにはその記述がない。ハルシネーション抑制はシステムプロンプト側の
  「FAQにない情報は絶対に答えない」制約のみで担保することになるため、T-12 で必ず検証する。

- **#8 は複数FAQを同時に参照できるかを見る。**
  FAQ取得は上位1件ではなく `is_active = TRUE` の全18件をプロンプトに渡す方式（T-11）のため、
  仕組み上は成立する。回答が片方だけにならないか確認する。
