# AI応答 検証シナリオ（8件）

AIの回答生成・エスカレーション判定・営業時間判定を確認するための8件です。
受入条件 **AC-001〜AC-006** に対応します。

`lib/prompt.ts`（システムプロンプト）や AIモデルを変更したら、この8件を通し直してください。
AIの回答根拠は `supabase/seed.sql` に投入済みのFAQ18件がすべてです。

---

## 判定の3種類

AIは必ず次の3つのどれかを返します。シナリオの期待値はこの `action` で表します。

| action | 意味 | 会話ステータス | 管理画面 |
|---|---|---|---|
| `answer` | FAQを根拠に回答して完結する | `ai_handling` のまま | 上がらない |
| `handoff_offer` | FAQを案内したうえで、担当者につなぐかを顧客に選ばせる | `ai_handling` のまま | 顧客が選ぶまで上がらない |
| `escalate` | AIでは対応できないと判断して人間へ回す | `waiting_operator` | 上がる |

## 精度目標と実測値

提案時の目標は **FAQベース応答で70%以上を自動応答**（`project-overview.md`：月500件のうち約350件をAIが処理）。

### 台本での実測（2026-09-01・本番環境）

測定は `_verify.local/verify-ai-scenarios.js` を本番URLに対して実行。台本8件に #7 の別文面1件を加えた計9件。

| 指標 | 定義 | 実測 | 目標 | 判定 |
|---|---|---|---|---|
| FAQ該当質問の自動応答率 | FAQ18件に根拠がある質問に、AIがFAQを根拠に回答できた割合 | #1・#2・#3・#8 → **4/4（100%）** | 70% | **達成** |
| FAQ非該当質問の引き継ぎ率 | 根拠がない質問を、推測で答えず引き継げた割合 | #4・#5・#6 → **3/3（100%）** | — | ハルシネーション **0件** |
| 判定一致率 | 期待した `action` と実際が一致した割合 | **9/9（100%）** | — | — |
| 人手を介さず完結した割合 | `action` が `answer` で終わった割合 | #1・#2・#8 → **3/8（37.5%）** | — | 下の注意を参照 |

### この数字で言えること・言えないこと

**言えること。** FAQに根拠がある質問は、すべてFAQを根拠に自動応答できました。根拠のない質問を推測で `answer` してしまったケースは0件です。目標70%はこの指標で達成しています。

**言えないこと。** 事業目標の「月500件の70%を自動対応」は**この台本では測れません。** 台本8件のうち5件（#3〜#7）は引き継ぎ・時間外・ハルシネーションを狙って作った異常系で、実際の問い合わせの構成比ではないからです。母集団が違うものから比率は出せません。

上の表で「人手を介さず完結 37.5%」となるのはそのためで、**AIの精度が低いのではなく、台本が難しい質問に寄せてある**ことを表しています。この数字を自動対応率として報告しないでください。

70%という数字自体は `project-overview.md` の想定値です（FAQで対応可能なカテゴリが90%、そこから保守的に70%と見積もり）。実測するには本番の問い合わせを一定期間ためて、オペレーターの発言が1件もない会話の割合を数えます。

```sql
-- 直近30日の自動対応率（オペレーターが一度も発言しなかった会話の割合）
SELECT
  count(*) AS total,
  round(100.0 * count(*) FILTER (
    WHERE NOT EXISTS (
      SELECT 1 FROM public.messages m
      WHERE m.conversation_id = c.id AND m.sender_type = 'operator'
    )
  ) / nullif(count(*), 0), 1) AS ai_only_pct
FROM public.conversations c
WHERE c.created_at >= now() - interval '30 days';
```

## シナリオ別の補足

### #3・#4 — 文面は似ているが挙動が逆になる

| | #3 破損 | #4 請求二重 |
|---|---|---|
| FAQの記載 | **ある**（No.9） | **ない** |
| AIの動き | 謝罪＋FAQの手順を案内し、選択肢を出す | 即エスカレーション |
| ステータス | `ai_handling` のまま | `waiting_operator` |
| 管理画面 | 顧客が選ぶまで上がらない | すぐ上がる |

この線引きは「FAQに書かれていないことは答えない」というシステムプロンプトの制約で担保しています。

**検証時は2点セットで確認してください。** AIの回答本文が出ていること、**かつ**ステータスが `ai_handling` のままであること。片方だけでは #3 が #4 に化けていても気づけません。

### #4・#5 — 引き継ぎの理由が違う

どちらも `escalate` → `waiting_operator` ですが、判定根拠が異なります。

- **#4** … FAQに該当なし（知識の不足）
- **#5** … 感情的なクレーム（内容の性質）

同じ結果になるため、片方だけ通っても両方通ったことにはなりません。必ず2件とも送ってください。

### #6 — ハルシネーション抑制の最終防波堤

正式FAQには「個別のご事情は担当者が対応します」のような逃げ道が書かれていません。そのため無関係な質問に対する抑制は、システムプロンプトの「FAQにない情報は絶対に答えない」制約**だけ**で成り立っています。

プロンプトを緩めると真っ先に落ちるのがこのシナリオです。`lib/prompt.ts` を触ったら必ず確認してください。

### #7 — 時間外案内はバナーに出る

**メッセージ本文だけを見ると、実装が正しくても失敗と誤判定します。**

営業時間外の案内文が**本文に差し込まれるのは `escalate` と判定されたときだけ**です（`actions/chat.ts`）。`answer` や `handoff_offer` のときは本文に入りません。

一方でパネル上部の時間外バナーは、判定にかかわらず常に表示されます。文面は本文に差し込まれるものと同じです。

```
現在は営業時間外です。翌営業日（10:00以降）に担当者が対応します。
```

顧客が見るのはパネル全体なので、**AC-006 の確認はバナーの表示で行ってください。** #7 の `action` が何になっても構いません。

### #8 — 複数FAQを同時に参照できるか

FAQは上位1件だけを渡すのではなく、`is_active = TRUE` の全18件をプロンプトに渡しています。仕組みのうえでは2件同時参照は成立します。**回答が片方だけになっていないか**を見てください。
