# AI応答 検証シナリオ（8件）

AIの回答生成・エスカレーション判定・営業時間判定を確認するための8件です。
受入条件 **AC-001〜AC-006** に対応します。

`lib/prompt.ts`（システムプロンプト）や AIモデルを変更したら、この8件を通し直してください。
AIの回答根拠は `supabase/seed.sql` に投入済みのFAQ18件がすべてです。

---

## 判定の3種類

AIは必ず次の3つのどれかを返します。シナリオの期待値はこの `action` で表します。

| action | 意味 | 会話ステータス | 管理画面 |
|---|---|---|---|
| `answer` | FAQを根拠に回答して完結する | `ai_handling` のまま | 上がらない |
| `handoff_offer` | FAQを案内したうえで、担当者につなぐかを顧客に選ばせる | `ai_handling` のまま | 顧客が選ぶまで上がらない |
| `escalate` | AIでは対応できないと判断して人間へ回す | `waiting_operator` | 上がる |

## シナリオ別の補足

### #3・#4 — 文面は似ているが挙動が逆になる

| | #3 破損 | #4 請求二重 |
|---|---|---|
| FAQの記載 | **ある**（No.9） | **ない** |
| AIの動き | 謝罪＋FAQの手順を案内し、選択肢を出す | 即エスカレーション |
| ステータス | `ai_handling` のまま | `waiting_operator` |
| 管理画面 | 顧客が選ぶまで上がらない | すぐ上がる |

この線引きは「FAQに書かれていないことは答えない」というシステムプロンプトの制約で担保しています。

**検証時は2点セットで確認してください。** AIの回答本文が出ていること、**かつ**ステータスが `ai_handling` のままであること。片方だけでは #3 が #4 に化けていても気づけません。

### #4・#5 — 引き継ぎの理由が違う

どちらも `escalate` → `waiting_operator` ですが、判定根拠が異なります。

- **#4** … FAQに該当なし（知識の不足）
- **#5** … 感情的なクレーム（内容の性質）

同じ結果になるため、片方だけ通っても両方通ったことにはなりません。必ず2件とも送ってください。

### #6 — ハルシネーション抑制の最終防波堤

正式FAQには「個別のご事情は担当者が対応します」のような逃げ道が書かれていません。そのため無関係な質問に対する抑制は、システムプロンプトの「FAQにない情報は絶対に答えない」制約**だけ**で成り立っています。

プロンプトを緩めると真っ先に落ちるのがこのシナリオです。`lib/prompt.ts` を触ったら必ず確認してください。

### #7 — 時間外案内はバナーに出る

**メッセージ本文だけを見ると、実装が正しくても失敗と誤判定します。**

営業時間外の案内文が**本文に差し込まれるのは `escalate` と判定されたときだけ**です（`actions/chat.ts`）。`answer` や `handoff_offer` のときは本文に入りません。

一方でパネル上部の時間外バナーは、判定にかかわらず常に表示されます。文面は本文に差し込まれるものと同じです。

```
現在は営業時間外です。翌営業日（10:00以降）に担当者が対応します。
```

顧客が見るのはパネル全体なので、**AC-006 の確認はバナーの表示で行ってください。** #7 の `action` が何になっても構いません。

### #8 — 複数FAQを同時に参照できるか

FAQは上位1件だけを渡すのではなく、`is_active = TRUE` の全18件をプロンプトに渡しています。仕組みのうえでは2件同時参照は成立します。**回答が片方だけになっていないか**を見てください。
